# 库存补货计划

在断货之前就知道该补什么货。把库存表和销售明细放在一起，算出每个商品的日均销量、还能卖几天，以及按交货期和安全库存得出的再订货点。需要补货的商品给出建议数量——够卖接下来几周，并按整箱和供应商起订量取整；数量可以手动改。还会提醒哪些商品在新货到之前就会断货。按供应商导出采购单 PDF 和补货计划 Excel。在本地运行，不用登录 ERP，无需 API 密钥。

## 功能

- **按历史算日均销量**：销售明细（日期、货号、数量）按最近 N 天平均；也可以直接用库存表里的日均或 30 天销量。
- **再订货点**：日均销量 ×（交货期 + 安全天数）；在途数量算作已有库存。
- **建议补货量**：补到够卖接下来 N 天，按整箱向上取整、不低于起订量；填写订货数量即可手动修改。
- **提醒**：到货前会断货、低于起订量或不是整箱、库存为负、没有供应商、销量表里有但库存表里没有的货号。
- **采购单**：每个供应商一份 PDF，含单号、按最长交货期算出的到货日期、箱数、单价、合计和签字栏。
- **Excel**：完整补货计划（可卖天数、再订货点、建议和订货数量），断货风险标红，另附每个供应商一张表。
- **面板**：在 ZCode 侧栏里选择输入文件、调整设置、查看问题、直接修改表格里的任意单元格、预览成品并导出。修改保存在 `inventory-reorder/<项目>.project.json`，重新打开输入文件前一直保留。

## 使用方法

在 ZCode 桌面端对助手说：

- “用 stock.xlsx 和 sales.xlsx 做补货计划”
- “安全库存留 10 天，每次补够 45 天”
- “按供应商生成采购单”

## 工具

| 工具 | 作用 |
|---|---|
| `reorder_open` | 读取库存和销量，给出补货建议，并打开面板 |
| `reorder_edit` | 修改设置、按行修改单元格、新增或删除行 |
| `reorder_status` | 查看当前数据、问题和汇总 |
| `reorder_export` | 导出每个供应商的采购单 PDF 和 reorder-plan.xlsx |

导出文件写到工作区的 `inventory-reorder/<项目>/` 文件夹。

## 范围（v0.1）

- v0.1 按简单平均估计销量，不预测季节性或促销。
- 每个项目只算一个仓库。

## 隐私、网络与文件

- **全部在本地运行。** 不联网、不上传，不需要 API 密钥或账号。
- 只读取你选择的文件，只写入工作区的 `inventory-reorder/` 文件夹。没有 Hook。

## 构建与测试（开发者）

- 源码：`ui-plugins/inventory-reorder/`。
- 构建：`pnpm install --frozen-lockfile && pnpm build`，然后把 `dist/local-marketplace` 添加为本地来源。
- 测试：`pnpm --filter @penova/plugin-inventory-reorder test` 和 `test:e2e`（需要 Chrome；样例文件在 `test/samples/`）。
