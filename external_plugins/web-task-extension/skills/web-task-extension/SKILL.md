# 网页操作转浏览器扩展

1. 先问清楚流程：从哪个网址开始，依次点什么、填什么，要提取哪些字段，是否翻页，最后存成什么文件。每次运行可能变化的值（搜索词、分类、日期）做成设置项，步骤里用 `{{key}}` 引用。不要把密码或验证码写进任务：登录不在范围内，请用户运行前自己登录。
2. 选择器尽量稳定：优先用 id、name、data-* 和语义化的 class；如果用户能提供页面 HTML 或网址，先读一下再写选择器。表格数据用 `extract`：`selector` 写成每行一个元素（如 `table tr.item`），`fields` 写成 `{ "列名": "td.price" }`，取属性写 `"a@href"`；需要翻页时加 `next`（下一页按钮）和 `maxPages`。可能出现也可能不出现的元素（如 Cookie 横幅），点击步骤加 `optional: true`。
3. 调用 `ext_new({name, description, steps, settings?, sites?})`。如果步骤会通过点击跳转到其他网站，把这些网站加进 `sites`。工具返回 `bad_task` 时，按提示修正后再调用。
4. 报告结果：扩展所在文件夹和 zip、申请了哪些权限及原因、校验结果（有“!”提醒的说明一下），以及加载方法：`chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 → 选择文件夹 → 固定图标 → 运行任务。
5. 用户要修改时用 `ext_update({out, steps?, settings?, sites?, name?})`，会自动升级版本号，提醒用户在扩展页点刷新。用户手动改过文件后用 `ext_check({out})` 重新校验。
6. 不在范围内的需求要直接说明：自动登录、验证码、定时运行、发布到商店（zip 已备好，由用户自己决定是否发布）。
