# 文档版本对照

对照合同、方案、制度或书稿的两个版本，逐条审阅每一处改动。

## 功能

- **输入**：`.docx`、带文字层的 `.pdf`、`.md` 和 `.txt`。两个版本可以是不同格式，比如你发出去的 DOCX 和对方改回来的 PDF。
  - DOCX：读取正文段落和表格单元格，修订按“全部接受”处理；已删除的文字和域代码会被忽略。
  - PDF：
    - 按行距、项目符号、缩进、字体变化和分页，把文字行还原成段落。
    - 去掉每页重复的页眉、页脚和页码，连上行末断词。
    - 部分 PDF 字体会输出部首码位（如 ⻘、⽅），这些会还原成正常汉字。
- **段落对齐**：
  - 先匹配没有改动的段落，剩下的按相似度配对。改过的段落显示为“修改”，而不是一删一增。
  - 能识别移动过位置的段落。
- **字词级差异**：英文按词、中日韩按字比较。涉及**数字**的改动（金额、日期、比例、中文数字）用 # 标出。
- **审阅面板**：
  - 改动清单，可按类型、数字、审阅状态筛选。
  - 左右对齐的原文对照，未改动的部分折叠，点击可展开。
  - 点一条改动，两边原文都会跳到对应位置。
  - 每条改动可以点“✓ 确认”或“? 疑问”，并写备注。
  - 审阅标记会保存，重新对照后仍然保留。
- **报告**：
  - HTML：高亮增删，带状态和备注，可以直接打印。
  - CSV：可用 Excel 打开。
  - 可以只导出未确认或有疑问的改动。
- 选项：忽略大小写、忽略标点。

## 使用

在 ZCode Desktop 里对 Agent 说：

- “对比 合同-v1.docx 和 合同-v2.pdf，把涉及金额和日期的改动标出来”
- “2026 版服务条款比 2025 版改了什么？涉及数据和 AI 的改动标成有疑问”
- “只导出有疑问的改动，生成对照报告”

## 工具

| 工具 | 作用 |
|---|---|
| `compare_open` | 对照两个文件，列出每处改动及其 id，打开审阅面板 |
| `compare_review` | 把改动标为已确认 / 有疑问 / 未确认，并写备注 |
| `compare_export` | 写出 `doc-compare/<旧>__<新>.html` 和/或 `.csv` |

## 范围（v0.1）

- 不支持没有文字层的扫描 PDF（OCR）。
- 不比较纯格式改动（加粗、字体），也不做表格单元格级对齐。
- 不写回带修订标记的 DOCX。
- 旧版 `.doc`、`.pages`、`.rtf`：请先另存为 DOCX。

## 隐私、网络与文件

- **全部在本地运行。** 不联网、不上传，不需要 API 密钥或账号。
- 只读取你选择的两个文件；只写入工作区里的 `doc-compare/`（审阅标记和报告）。没有 hooks。

## 构建与测试（开发者）

- 源码：`ui-plugins/doc-compare/`。
- 构建：`pnpm install --frozen-lockfile && pnpm build`，再把 `dist/local-marketplace` 添加为本地来源。
- 测试：`pnpm --filter @penova/plugin-doc-compare test` 和 `test:e2e`。
- `DOC_SAMPLES` 指向测试文档，包括：
  - GitHub 服务条款的两个版本（CC0），各有 Markdown、DOCX 和 PDF。
  - 虚构的中文合同两版。
