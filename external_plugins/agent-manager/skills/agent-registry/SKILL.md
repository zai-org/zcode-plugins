# 智能体定义管家

管理智能体(subagent)的 Markdown 定义文件。每份定义 = YAML frontmatter(名称、职责等)+ 正文系统提示词。

## 定义文件位置(作用域)

| 作用域 | 目录 | 权限 |
|---|---|---|
| 用户级 | `~/.zcode/agents/*.md`(Windows 下通常为 `C:\Users\<你>\.zcode\agents\`) | 可读写,全局生效 |
| 工作区级 | `<工作区>/.zcode/agents/*.md` | 可读写,仅本工作区生效;目录不存在时按需创建 |
| 插件自带 | ZCode 插件缓存目录下的 agents | 只读:可盘点,不要修改 |

工作区未知时用当前会话的工作目录。插件缓存路径不要凭空猜测,只盘点实际确认存在的文件。

## 定义格式(以本机现有文件实测为准)

```markdown
---
name: "crawl"             # 必填,小写连字符,应与文件名同名
description: "一句话职责"   # 必填,主会话据此决定派不派它
color: yellow             # 可选
injectAgentsMd: true      # 可选
tools: Read, Bash         # 可选,逗号分隔;缺省继承全部工具
---

正文 = 该智能体的系统提示词(人设、职责、约束、输出要求)。
```

## 操作流程

### 盘点(list)
1. 扫描上述目录的 `*.md`,只统计真实存在的文件。
2. 逐个读 frontmatter,输出表格:名称 | 作用域 | 工具 | 一句话职责。
3. 同名出现在多个作用域时标 ⚠️,提示用户确认哪个生效;不要编造作用域优先级规则。
4. 会话系统提示里的「Available agent types」是运行时的权威清单:盘点结论要和它对账,差异要说明(例如插件运行时注入的智能体在磁盘上没有对应文件)。

### 查看(show <名称>)
定位并完整展示 frontmatter 与正文;找不到时列出相近名称供选择。

### 新建(new)
1. 向用户确认:名称、一句话职责、系统提示词要点、需要哪些工具、作用域(默认用户级)。
2. 按上面模板写文件;文件名 = name = 小写连字符。
3. 写完回读确认落盘,并提醒用户:新智能体通常要到下个会话才出现在可用列表中。

### 修改(edit <名称>)
先读原文,用最小编辑修改,改完展示改动供用户确认。保留用户已有的 frontmatter 字段,不顺手重排。

### 校验(check)
对每个 `*.md` 检查:
- frontmatter 存在且可解析;name、description 非空;
- name 与文件名一致(不一致给警告,不擅自改名);
- 正文非空;
- tools 里出现的都是本环境真实存在的工具名;
- 无未解析占位符、无乱码或编码异常。

每个文件输出一行:通过 / 警告 / 失败,附 `文件:行号` 证据。只报告,不擅自修复。

### 删除(delete <名称>)
先展示文件内容并获得用户明确确认后才删除;优先建议「改 description 让它不再被派发」而不是物理删除。
