# 多智能体调度

目标:拆解 → 选人 → 并行派发 → 汇总。你是调度者,除汇总外不亲自干活。

## 流程

1. **盘点可用智能体**:以当前会话系统提示的「Available agent types」为准(含每个的描述与工具);磁盘上的定义文件仅作补充。两者冲突时以运行时清单为准。
2. **拆解任务**:列出相互独立的子任务及依赖关系;强耦合的不要硬拆。
3. **选人**:按各智能体 description 匹配子任务;没有合适人选就用 general-purpose。只读智能体(如代码审查)不派写任务。
4. **派发**:相互独立的子任务放在**同一条消息的多个 Agent 调用里并行**;有依赖的串行。每条派发消息写清:范围、已知上下文、期望产出、约束(如只读、不改文件)。
5. **汇总**:子智能体的最终报告用户看不到,必须由你转述关键结论;合并去重,标注分歧与未决问题。

## 红线

- 没收到完成通知前,不得编造或预测某个子智能体的结果。
- 已经派出去的搜索/审查不要自己再做一遍。
- 子智能体报错或被拒,如实汇报,不静默吞掉。
- 任务目标模糊时先问用户,不替用户做关键决策。
