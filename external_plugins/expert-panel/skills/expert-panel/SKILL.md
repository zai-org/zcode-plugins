# expert-panel —— 专家团共识评审

## 机制（为什么可信）

1. **独立作答**：N 位不同视角专家先各自独立表态，互不知晓（无从众）。
2. **真匿名互评**：互评输入只有「专家A/B/C」标签 + 立场 + 要点，不含视角名（防权威偏置）；各自提出反对/补充并按说服力排序。
3. **仲裁归纳**：归纳为一致项/分歧项。**共识率 = 一致/(一致+分歧)，由脚本确定性计算，不信模型自报**。
4. **共识率门控加辩**：低于阈值（默认 0.6）自动加辩一轮，仍不足则**明示分歧交人工裁决，绝不硬合成**。
5. **主席综合**：执行摘要 + 最终建议。
6. **事实复核**：可客观验证的一致项由复核员核验（能读文件/跑命令就去验），不实的剔除；价值判断类标 unverifiable 原样保留。

单专家失败自动容错，结论标注样本完整度（缺席视角/有效专家数）。

## 怎么调用

工作流文件随本插件分发：**本 skill 目录的 `../../workflows/expert-panel.dwf.ts`**（相对本 SKILL.md）。

用 `CreateWorkflow` 的 **path 方式**调用（不要复制进用户的 workflows 目录，升级由插件统一管）：

```
CreateWorkflow(
  path = <按上述相对位置解析出的绝对路径>,
  name = "专家团",
  args = { question, profile, ... }
)
```

### 参数

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| question | string | 必填 | 要专家团给出稳定结论的问题/决策 |
| profile | string | standard | quick（3 专家/1 轮，数分钟）\| standard（2 轮）\| deep（自动补反方质询+综合连接原型，2 轮） |
| experts | json | [务实工程师, 风险与边界审查, 产品价值] | 专家视角名数组（勿重复） |
| threshold | number | 0.6 | 共识率阈值，低于自动加辩一轮 |
| max_rounds | number | quick=1，其余=2 | 最大轮数（含首轮） |
| evidence | json | 空 | 证据包：文本或文件路径数组（专家/复核员用工具自行读取） |
| basis | json | 空 | 评测依据：文件路径或条目数组，给了就要求逐条对照判定并引用条目 |
| ledger_path | string | ~/.expert-panel/ledger.jsonl | 运行台账 JSONL 落盘路径 |
| simulate_failures | json | 空 | 测试用：要模拟作答失败的专家下标数组 |

### 模型选择（可选）

所有角色默认用**会话默认模型，零配置可跑**。要统一换模型：在 `CreateWorkflow` 调用上传 `subagent_model`（id 用 `ListModels` 查当前 provider 的行）。
注意：按角色分模型（如互评用轻量模型）是宿主刻意不支持的——子代理模型必须在运行前已知；请勿尝试在脚本里做运行时路由。

### 结果解读

- `agreementRate ≥ threshold`：达成共识，`agreed` 为经复核的稳定结论；`unverifiable` 是价值判断类。
- `< threshold`：`disputed` 已列明各方论据，交人工裁决——这是特性不是失败。
- `absent` 非空或有效专家 < 2：结论已标注样本完整度，引用时注意口径。
- 每轮运行一行追加台账（`ledger_path`）：问题摘要/档位/专家数/轮数/共识率/一致分歧计数。

## 边界

- 价值判断类结论无法客观复核（标 unverifiable），仅代表专家团意见。
- 台账写入失败不阻断结论（结果 `verified` 里会注明未入账）。
- 深档会显著增加 token 消耗，重要决策再用。
