# ZCode 用量明细查询

数据源是 ZCode 客户端本地 SQLite（默认 `~/.zcode/cli/db/db.sqlite`，可用环境变量 `ZCODE_USAGE_DB` 覆盖）的 `model_usage` 表：每次模型请求一行，含时间、所属会话、模型、输入/生成/缓存读 token、耗时与状态。套餐服务端配额（5 小时池/周额度）不在此库中，需引导用户查看 ZCode 的 Usage Stats → Coding Plan。

## 查询方法

运行本插件自带脚本。对本技能文件所在目录而言，脚本位于 `../../scripts/usage.sh`；若 `${ZCODE_PLUGIN_ROOT}` 可展开，也可写成 `bash "${ZCODE_PLUGIN_ROOT}/scripts/usage.sh"`。

```bash
bash "<本技能目录>/../../scripts/usage.sh" <子命令> [参数]
```

子命令与用户意图的映射：

| 子命令 | 用途 | 用户说法示例 |
|---|---|---|
| `this [--session ID \| --directory DIR]` | 当前会话文本汇总 | "这个会话用了多少 token" |
| `dashboard-this <输出.html> [--session ID \| --directory DIR]` | 当前会话仪表盘 | "图形化看看本次会话用量" |
| `dashboard <输出.html>` | 生成交互式仪表盘（HTML 片段） | "界面看看"、"仪表盘"、"图形化" |
| `summary` | 总览：累计 + 今日（默认） | "我的用量怎么样" |
| `providers` | 按来源汇总（官方套餐 / 自定义接入） | "官方套餐和 API Key 各用了多少" |
| `blocks` | 5 小时窗口用量（本地近似口径：相邻请求间隔≥5h 切分，与官方窗口起点可能不一致；界面已不展示） | "这个 5 小时周期大概用了多少" |
| `months` | 按月汇总 | "这个月用了多少" |
| `projects [N]` | 按项目目录汇总 Top N（默认 15） | "哪个项目最烧 token" |
| `tools [N]` | 工具调用统计 Top N（默认 15） | "最常用的工具是什么" |
| `cost` | 按模型折算成本（GLM 5.3 系智谱官方牌价 CNY，其余 models.dev 换算；~/.zcode/usage-prices.json 可覆盖/扩展） | "估算一下花了多少钱" |
| `prices [show\|sync]` | 查看价格表 / 从 models.dev 同步官方价 | "更新一下官方价格" |
| `live [秒]` | 终端实时燃烧率监控（默认 3s 刷新）。**只在用户明确要实时监控且在终端运行时使用，不要在会话里执行（会一直阻塞）** | "帮我盯着燃烧率" |
| `serve [端口]` | 本地常驻面板（默认 7741，浏览器打开、5s 轮询实时燃烧率）。用户要"常驻看板/实时面板/浏览器打开"时使用：以后台方式启动（run_in_background），把 http://127.0.0.1:7741 以 Markdown 链接交付，并说明仅监听本机、停止方式 | "我要一个常驻的用量看板" |
| `turnstats [notify|inject|off|status]` | 每轮统计附加出口：notify=每轮结束弹系统通知（本地计算，零模型开销，推荐）；inject=对话内统计行（每轮约 0.3k token）；off=仅侧栏面板「本轮」实时卡（始终开启）；默认 off | "打开/关闭每轮统计" |
| `waste [N]` | 浪费取证：近 N 天（默认 7）失败/取消/重试白耗 token、反复失败会话 Top5、重试最多模型 | "浪费/失败请求分析" |
| `alerts <budget|permission> [on|off|status]` | 通知开关：预算 80%/100% 与燃烧告警（默认开，本地检查）、权限等待提醒（默认关） | "打开预算告警/权限提醒" |
| `doctor` | 环境自检（"统计不见了/数字不对吗"先跑这个）：数据库与表结构、价格表时效、配额数据源、node 依赖逐项排查 | "统计好像不对"、"怎么没数据了" |
| `quota` | 查询 Coding Plan 套餐配额余量（智谱官方监控接口）。桌面 OAuth 不适用于该接口，用户以 API Key 接入且写了 ~/.zcode/usage-quota-token.json（`{"token":"KEY","base":"https://open.bigmodel.cn"}`）时才可用；未配置时如实说明并引导用 Usage Stats → Coding Plan | "套餐还剩多少额度" |
| `export csv\|json [路径]` | 导出全部记录 | "导出成 CSV" |
| `recent [N]` | 最近 N 条逐条明细（默认 20） | "看每条记录"、"最近 50 条" |
| `day [YYYY-MM-DD]` | 某天逐条明细（缺省今天） | "今天用了多少"、"看 10 月 14 日的" |
| `days [N]` | 最近 N 天按天汇总（默认 14） | "最近一周每天的用量" |
| `sessions [N]` | 按会话用量 Top N（默认 15） | "哪个会话最烧 token" |
| `models` | 按模型汇总 | "各模型的 token 分布" |
| `errors [N]` | 最近 N 条失败请求（默认 10） | "有没有报错的请求" |

## 当前会话

`/usage-this` 使用 `this`；`/usage-this-ui` 使用 `dashboard-this`，共用插件脚本，会话 UI 使用独立的精简面板：

```bash
bash "<本技能目录>/../../scripts/usage.sh" this
bash "<本技能目录>/../../scripts/usage.sh" dashboard-this "<可视化目录>/usage-this-dashboard.html"
```

- 默认选择 `model_usage` 中 `started_at` 最新的请求所属会话，并在一次执行中固定该 ID。ZCode 命令环境尚无可靠的当前会话 ID，此方式为推断；多窗口同时请求时可能选中其他会话。报告中保留会话标题、ID、最近请求和定位方式，提醒用户核对。
- 用户明确给出会话 ID 时追加 `--session "<ID>"`；用户明确要求限制项目时追加 `--directory "<项目绝对路径>"`，选择该目录内最近请求所属会话。这两个参数互斥。将参数值作为单个 shell 参数传入，按 shell 规则引用，避免把用户文本直接拼接为命令。
- 仅统计所选 `session_id`，包括其主会话/子代理/系统请求；不递归合并其他 `session_id` 的子会话。
- 文本汇总与模型/来源分组统计全部状态；失败/取消列表最多 10 条。进行中的请求单独计入其他状态，后续快照可能变化。
- UI 首屏展示会话标题、最近请求和请求数/输入/生成/缓存读四项统计；会话 ID、目录、创建时间可展开核对，模型分布和请求明细默认折叠。失败/取消入口会展开明细并应用对应筛选。全量分析功能使用 `/usage-ui`。
- UI 在数据库查询时先过滤会话，再截取最近请求（默认全部历史，`ZCODE_USAGE_LIMIT` 可限制为 1-20000 或 -1 全部）；元数据也限定为同一会话。卡片和明细只统计已加载记录，截断时面板明确提示。
- 无请求时自动定位会报错；显式指定已存在但没有请求的会话可查看零用量。查询失败时如实报告。

UI 的输出目录和最终引用按下节执行。

## 仪表盘界面（dashboard / dashboard-this）

用户想以界面/图表形式查看用量时使用：

1. 从宿主上下文找到本次会话的可视化输出目录（形如 `~/.zcode/v2/visualizations/<id>`，必须写入该目录），执行：

   ```bash
   bash "<本技能目录>/../../scripts/usage.sh" dashboard "<可视化目录>/usage-dashboard.html" [条数]
   ```

   条数控制内嵌的最近请求行数（默认 -1 全部，范围 1-20000，可用环境变量 ZCODE_USAGE_LIMIT 覆盖默认值）。超过约 8000 条可能超出会话内嵌渲染的体积限制，更大的历史请改用 `export json`。

2. 在**最终回复**中单独一行输出内容引用（不要放进代码块），宿主会将片段内嵌渲染：

   ```text
   ::visualize{"path":"<可视化目录>/usage-dashboard.html"}
   ```

3. 仪表盘数据在生成时已内嵌，无网络请求。`dashboard` 包含总览/每日趋势（含每日明细表）/会话排行/请求明细/失败请求五个全量分析标签页，会话行与请求行可点击展开详情（上下文压缩、模型占比、工具、水位曲线；请求级含 Token 构成与时序），热力图/趋势图/时段分布悬停显示明细；`dashboard-this` 使用四项统计和折叠明细的精简会话面板。
4. 仪表盘顶部的实时配额条优先零密钥读客户端日志（来源标注"客户端日志"）；不可用时显示降级提示，属预期行为，可建议用户运行 `/usage doctor` 排查。
5. 若界面元信息显示"已加载 X / Y 条"且 Y 明显大于 X，主动告知用户：可指定更大条数重新生成，或用 `export json` 导出全量。
6. 若宿主未提供会话可视化目录，退化为普通交付：把生成的文件绝对路径作为 Markdown 链接告知用户，用浏览器打开。
7. 生成的界面是快照；用户要最新数据时重新执行 dashboard 覆盖同一文件，并在最终回复再次引用。

## 每轮统计（实时卡 / 通知 / 统计行）

每轮回合结束由 async Stop 钩子本地统计：侧栏面板顶部「⏱ 本轮」横幅经 MCP 资源订阅实时刷新（始终开启，零模型开销）；`turnstats notify` 加 macOS 系统通知（面板未开时的兜底）；`turnstats inject` 走对话内统计行——此时 hooks 会在每次提问时注入指令：模型在写最终回复正文前运行 `node <脚本目录>/../scripts/turn-stats.mjs --turn --current`，把输出的一行（`本轮用量：…`）原样放入引用块附在回复最末尾，且必须与正文同一条消息（否则客户端折叠正文）。脚本无输出（纯问答轮）时不显示统计行，也不要为此额外调用工具。

## 输出要求

- 数据库只读，不发起网络请求；仪表盘与导出仅写入调用方指定的输出文件。
- 结果用中文表格转述；用户要更多逐条记录时加大 N 即可，不要一次性倾倒全部历史。
- token 口径：输入列已含缓存命中（缓存读单独一列展示），生成 = 输出 + 思考。
- 数据库不存在或无法读取时如实报告原因，不要伪造数据。
