## 三个 id 是什么

| 源 | 载体 | 写者 | 语义 |
|---|---|---|---|
| **env 快照 id** | `CLAUDE_SESSION_ID` / `ZCODE_SESSION_ID`（进程环境） | 平台（会话 shell 快照建立时定格） | 会话**开局时**的身份快照；长对话续接换平台号后**可陈旧** |
| **relay 真身 id** | `regress-guard-session-<md5(project)>.json`（临时区，UserPromptSubmit 每轮原子重写） | 钩子侧（`session_relay.write_relay`） | 当前在该项目说话的会话**最新真值**（last-writer-wins + 5min 新鲜窗） |
| **清单 session 戳 / lease holder** | 清单 frontmatter `session:` / lease 块 | 盖章侧（`plan_approve`，relay 优先） | 清单归属的**登记事实**，判等的对照面 |

## 判等规则（守卫侧，`session_relay.my_sids` 单一实现）

1. **单源**：任一源单独在场即该源为身份——relay 无 id（新会话冷启）回退 env。
2. **双源一致**：同一 id，无歧义。
3. **双源冲突**（新鲜 relay ≠ env）：**relay 真身为准，env 陈旧即弃**——
   relay 每轮写后重盖=最新真值。效果：Bash 写通道对真身会话直通，
   「中继重盖真身 id → 守卫比 env 旧 id 误拦 → 绕 Edit 通道」的对抗循环消除。
4. **新鲜窗**：relay 仅 5min 内有效；窗外=陈旧中继不得代言（会话切换后
   旧号失效语义保留）。
5. **只读判等**：守卫侧判等不写回 relay、不继承进持久化戳（防中继回翻污染）。

## 写入规则（盖章侧）

- 清单 session 戳 / lease holder 一律 **relay 优先、env 兜底**
  （`plan_approve`：`read_relay(...).sid or sid_from_env()`）。
- 守卫侧任何代码**不得**写 relay（写者只有 UserPromptSubmit 钩子）。

## 已知边界（backlog）

- last-writer-wins：两会话同项目并发时判等可能偏向最后说话者——错向是
  「自己被判他会话」（拦截可见可修），不是静默放行（顾问预审认可）。
- 治本方向（backlog）：单调序号 relay / shell 快照 env 刷新。
