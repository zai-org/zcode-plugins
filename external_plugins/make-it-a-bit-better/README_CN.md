<h1 align="center">make-it-a-bit-better（好一点点）</h1>

<p align="center"><strong>一轮好一点点，轮次积累成产品进步。</strong></p>

一个跑自主产品打磨循环的 skill 插件。每轮**强制开一场新头脑风暴**（3 个视角强制的子代理），**择一个小角度**，实现、验证并提交，落账到项目级 ledger。一轮装不下的好想法进 **icebox**，不硬塞。哲学就是名字本身：不做重写——一轮好一点点，轮次积累成产品进步。

## 为什么不直接让 agent「优化一下」？

即兴 prompt 也能改出一段代码，但给不了这个循环的三个结构保证：

- **每轮强制新风暴** — 3 个强制视角在上一轮的框架之外重新生成候选，再按账本去重；即兴 prompt 只会重炒模型上次说过的话。
- **一个小而验证过的改动** — ≤3 文件 / ≈100 行，真实检查必须通过，检查红了就回滚而不是带伤提交；即兴 prompt 优化的是「看起来做完了」。
- **跨轮记忆** — 账本记录碰过的维度、把超格想法停在冰柜，第 17 轮不会重复第 3 轮；即兴 prompt 每次从零开始。

## 输入

| 输入 | 默认 | 作用 |
|------|------|------|
| `target` | 当前工作目录 | 要打磨的仓路径。必须是 git 仓的根目录——非 git 目标、或嵌在别人的仓里的子目录，动工前就被拦下。 |
| `rounds N` | 1 | 跑几轮（说「N 轮」或「继续」皆可）。给了 N 就连跑满 N 轮不再询问；连续两轮风暴出不了合格候选会提前自停。 |
| `focus` | 无 | 要聚光的功能/路径（如刚上线的功能）。贯穿每个视角的风暴生成，区内候选排序优先——不只是接地时看一眼。 |

## 一轮长什么样

1. **接地** — 读产品、最近提交和账本；从没碰过的维度本轮优先。非 git 目标仓在动工前就被拦下。目标仓没有 README/文档时，接地降级为入口代码 + 目录树，并在轮报里说明——绝不凭空即兴编一段产品摘要。
2. **风暴（强制）** — 3 个新上下文子代理各戴一个视角镜头（初见用户、挑剔的日常用户、半年后的维护者、审查者、脚本调用方……），各自产出候选角度；按账本去重，不炒冷饭。客户端没有子代理工具时，退化为会话内三趟视角强制风暴。带 `focus` 的运行，每个视角的接地摘要都聚光该区。宽想之后还是瘦？冰柜里能切成单轮上限的好想法会被晋升落地，而不是让运行提前自停。
3. **择一** — 按感知面 × 新鲜度 ÷ 成本排序，单轮硬上限 ≤3 文件 / ≈100 行；超格好想法进 icebox。带 `focus` 时区内候选优先。
4. **落地** — 遵守目标仓自身规范，只留完整改动，不留 TODO / mock。
5. **验证** — 用目标仓自己的测试 / 构建 / lint / 冒烟；工具链缺失时如实报「验证待补」，不谎报；目标仓压根没有验证面（区别于工具链缺失）时，最低手动冒烟改动路径（真实命令 + 实际输出作为证据），实在无可执行对象（纯文档/文案改动）就如实落 `verification pending（无可执行验证面）`；检查红了先在单轮上限内修，修不好就零带伤离场：先以 `mabb #N: <角度>` 提交本轮改动，再以第二个 `mabb #N: revert` commit 原地反转（绝不 discard——失败 diff 留在历史里），落一条 failed 账——失败轮恰好两个 commit，绝不带伤提交。
6. **落账** — 一轮一 commit（`mabb #N: <角度>`）+ 一条账本记录（维度、角度、谁会感知、证据）。写账前用 `git check-ignore` 核实账本的 `.agents/` 位置已被忽略，缺规则就当轮补上（计入文件上限），agent 工作态绝不混进轮次 commit。
7. **续轮** — 默认问一次是否继续，给了 N 就连跑；连续两轮风暴出不了合格候选就自停，不硬凑弱改动。每轮以同构的 6 字段轮报收尾（角度 / 谁感受到 / 改了什么 / 证据 / icebox 新增 / 下轮提示；空字段写 `none` 不缺行），跨轮跨仓可比较。整场运行收尾（N 轮跑满、用户不续或自停）再以 4 字段运行总结块落幕（`rounds:` / `changes:` / `icebox added:` / `leftovers:`）——5 轮批量跑完有底线汇总，而非不了了之。自停时账本的「下轮提示」也会被改写为一行带日期的 `stalled`（为何贫瘠、下轮先宽想什么）——自停事实留档在对话之外，后续会话能区分「贫瘠自停」与「正常跑完」。

## 账本

目标仓的 `.agents/mabb/ledger.md` 是循环的记忆：防重复旧角度，覆盖视图逼着风暴往没碰过的维度去。icebox 存好但超格的想法，等你拍板升级成正式需求——某轮落地即销账，冰柜永远只列还没做的。冰柜条目带短 id（`IB-1`、`IB-2`……一旦分配不再变），轮报、下轮提示与晋升引用精确到条，不再靠描述性指认。

## 副作用披露（供评审）

- **模型调用**：每轮派 3 个短命头脑风暴子代理（无子代理工具的客户端退化为会话内三趟）——N 轮约 3N 次这样的调用。
- **文件**：在目标仓写改动本身，外加本地账本 `<target>/.agents/mabb/`。
- **Git**：每轮在目标仓落一个本地 commit（失败轮恰好两个：本轮 commit + 其 revert——失败 diff 留在历史，零带伤提交）；多人协作仓先提分支方案再动，绝不直提主干；**绝不 push**，除非你当次明说。
- **网络**：除模型 API 外无任何访问。
- **上下文**：技能文本每轮被执行 agent 整读，故带软顶（150 行）——超顶的增长须以蒸馏现有行来抵偿，小上下文 agent 永远装得下一轮。

## 安装

**DSH**——本仓即 DSH bundle：一个包挂载 `make-it-a-bit-better` 技能（纯技能——无 MCP server、无运行时依赖）。需要 DSH `>=0.2.1-rc.2 <0.3.0`。

```bash
# 从 checkout 安装
dsh plugin add /path/to/make-it-a-bit-better

# 发布后
dsh plugin add make-it-a-bit-better
```

**ZCode**——同一仓库兼作 ZCode 插件（`.zcode-plugin/plugin.json` + `skills/`）：从任一收录它的插件市场安装；本地试用可让 dev 市场指向一份 checkout。

## 快速开始

装好插件后：

> 对 /path/to/repo 跑 3 轮 make it a bit better

也可以带上方向盘：指定仓、要 N 轮、聚光一个区域：

> 对 /path/to/repo 跑 5 轮 make it a bit better，focus 在结账流程

预期：每轮一条账本记录，最多 N 个已提交的小改进——说「最多」是因为连续两轮风暴贫瘠会自停（账本留一行带日期的 `stalled`），检查红了修不好就整轮回滚（落一条 `failed, reverted`，零带伤提交）。commit 数少于 N 是循环在诚实，不是坏了。只有风暴产出超格想法时才会出现 icebox。
