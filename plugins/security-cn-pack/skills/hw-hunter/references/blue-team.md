# 蓝队篇：检测体系、产品线与应急

## 防守四阶段

**备战**（减攻击面）→ **临战**（演练）→ **决战**（监测响应）→ **总结**（加固闭环）

### 备战自查清单

- **资产梳理 SOP**：管理员原始表+SOC 导出 → 网段存活探测 → 全端口服务探测(1-65535) → **边界设备日志反查未登记资产** → 无归属资产关停下线。资产表字段：归属域/系统、IP（主备/浮动）、开放端口、Web URL、可访问位置及授权、防护手段（ACL/IPS/WAF）
- 暴露面收敛；非必需端口严格限制；重点筛 http/https/FTP/SMTP/RDP/数据库端口
- **弱口令清理**：字典=账号库+口令库（默认口令+行业口令+厂商口令+人名拼音/手机号）；工具 RSAS/Hscan/John；**扫描期临时关闭账号锁定策略，扫完立刻恢复**（红队的爆破窗口）
- **漏扫纪律**：重要资产夜间扫、邮件留痕授权、未扫过设备逐 IP、主备/浮动地址分开扫；误报五场景（OS 指纹错/Oracle 补丁号取不到/openssh 旧文件残留/定制版本集成修复/未启用受影响模块）；**防火墙代答制造假端口**（0 进度=不通，无漏洞=被阻断）
- **安全域与策略**：重要区域对互联网"原则上不允许"；四检查=策略合规（目的 IP/端口范围过大）、策略有效（扫描端口与开放端口一致）、安全设备有效、日志采集；多外网出口是攻击路径图
- **加固参数册**（四系统速查）：
  - Windows：gpedit 密码策略 8 位+3 类/90 天/5 次锁 30 分钟；RDP 改端口注册表 `WinStations\RDP-Tcp\PortNumber`；审核策略全开；防火墙禁 135/137/138/139/445
  - Linux：login.defs（PASS_MAX_DAYS 180/MIN_LEN 8）、umask 077、sshd PermitRootLogin no + MaxAuthTries 6、xinetd 关 telnet/tftp
  - Oracle：FAILED_LOGIN_ATTEMPTS 10、audit_trail=os、listener.ora 加 `SECURE_REGISTER_LISTENER_PROD=(TCP)/(IPC)`（TNS-01194=生效）
  - Apache：去 Options Indexes、`<Directory /> Deny`、TraceEnable Off、隐藏版本
- 高危靶对齐：MS17-010、Struts2、Weblogic T3 反序列化、Oracle TNS 投毒、Heartbleed、Memcached 11211

## 检测三角（体系的三根支柱与盲区）

1. **告警依赖设备规则启用**——未启用=无告警；日志未接入=盲区；私网 IP 未导入资产不产生事件（态势感知"资产+事件"双条件）
2. **二段式判定**：告警日志 + HTTP/会话日志关联 = 确认失陷
3. **统计特征**：源 IP 聚合、频率异常、响应码

### 各类攻击判定公式

| 攻击 | 判定 |
|------|------|
| Webshell 入侵 | Webshell URL + HTTP 主动访问 **200 OK**（非 200 漏报） |
| 挖矿 | 连接矿池（session 含 `"method":"mining.subscribe"`）+ DNS 请求链 |
| 永恒之蓝 | Ms17-010 利用 + doublepulsar 后门连接（会话下行包数>20 且上行流量>4k） |
| 扫描 | 源 IP 固定 + 访问频率异常 + 协议摘要含验证 payload |
| 工具爆破 | 错误认证时间隔小 + 源 IP 固定 |
| 失陷资产 | 连接方向内→外 且 攻击阶段 stage≥5 |

### 告警分析四步

过滤 → 时间排序 → 归并 → **源 IP 聚合**（多类型攻击=扫描器，随后骤降=手工渗透开始）。Excel 数据透视做多维聚合。

## 国产安全产品线职责（乙方面试常考，以绿盟系为例）

| 产品 | 职责 | 关键机制/盲区 |
|------|------|---------------|
| NTI | 威胁情报中心（SaaS） | IOC/基础情报/漏洞情报/咨讯；暴露面核查（高危主机=开 SSH/Telnet/RDP/SMB/数据库端口）；ADS 联动自动阻断 |
| TSA/态势感知 | 态势呈现 | 前提="资产+事件"；第三方日志需自定义 GROK 解析+事件规则 |
| IPS/NIPS | 特征+统计双机制 | 策略按优先级遍历任一阻断即断；**日志归并默认 3600 秒**；旁路 NIDS 只检测不阻断 |
| WAF | Web 防护 | 部署四模式（串联透明/旁路牵引/反代/镜像）；误报判断三步=匹配关键词→规则描述→HTTP 原文；调优=资产登记→只开高准确度规则→逐步开阻断 |
| ESPC | 统一管理平台 | 设备管理/日志报表/告警；危险度求和 M=3A+2B+C≥K 触发；实时监控只回看最近 2 小时 |
| TAC | 威胁分析沙箱 | 四引擎顺序=信誉→病毒→静态→动态；**白名单优先，命中不再检**；虚拟化只支持 API 上传 |
| UTS/TAM | 全流量 | UTS 探针存原始流量可 pcap 取证回溯；TAM 关联分析；复合事件（蠕虫/DNS 隐蔽信道/Webshell）需启用才告警 |

## 应急响应三要素法

- **时间**：攻击发现时间/后门文件时间/异常时间段——对齐 Web/系统/安全设备日志
- **地点**：恶意文件首次出现目录 → 反查上传点或代码执行点
- **事件**：应用后台登录日志 + 安全设备告警 + FTP/SSH/远程桌面日志 + web 运行账户

**排查优先目录**（攻击者常用落点）：`/var/tmp`、`C:\Users\*\Downloads`、tomcat `conf/tomcat-users.xml`、WebLogic `_WL_internal` war 目录、上传目录、中间件根目录。

**工具链**：Tcpview（外联）、AutoRuns（启动项）、D 盾/findwebshell（查马）、LogParser（`select * from security.evtx where EventID=5080`）、goaccess 出 html 报告。

**取证对象**：木马样本+全套日志+残留文件+抓包；处置=断网隔离→根除（修漏洞）→恢复（清马重置账号）。

## 事件分级与闭环

分级：4 级扫描、3 级爆破/钓鱼、2 级高危漏洞利用/木马、**1 级内网扫描/内网爆破/内网高危利用（最重）**。

闭环六阶段：准备→发现→报告→分析→处理→总结；处理=遏制（封 IP/URL）→根除→恢复。4 级备案后封禁、3 级封禁+查弱口令+升级判断、1 级木马定位+溯源+修复杂件。

**上报拿分要点**：上报源 IP+流量分析+样本才计分，只截设备告警图不计分；**1 小时内上报且取证完整可免扣分**（防守初始 5000 分：终端 10/台、Webshell 20/个、账密 20-60/个、域控管理员 300；加分=发现木马 50/处置 Webshell 50）。

## 蓝队反制（面试必考）

- **蜜罐**：伪造脆弱服务收集攻击者指纹与 0day（注意越权使用边界）
- **反渗透**：攻击 IP 反查身份（测绘/社工/IDC 备案）
- **反钓鱼**：邮件网关+员工上报（+20 分/起）
- **溯源链路**：C2 IP → 测绘定位 → IDC 备案/whois → 关联历史活动 → 攻击队画像
