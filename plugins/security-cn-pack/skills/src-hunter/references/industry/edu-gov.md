# 教育 / 政企行业 playbook（补天公益主战场）

> 视角：黑盒，面向补天公益 SRC 等收录 edu/国企单位的平台。
> 数据基础：JSRC/乌云教育行业案例 + 补天实战复盘。
> **合规前置**：公益平台只测平台列出的厂商资产；高校自建系统在未列入时一律不碰；gov 类关基设施永远不碰，发现信息泄露走报告不深入。

## 1. 资产范围推断法（详情页无范围时）

补天公益厂商详情页常不写资产范围。推断链：

1. 看厂商**主营产品**的官方域名（产品站页脚"技术支持：xx公司"）
2. 厂商客户是学校 → 产品部署域常在 `*.chaoxing.com`、`*.fanya.chaoxing.com` 类 **SaaS 域**下（厂商可控）——SaaS 域安全，客户自建域不在范围
3. 用 ICP 备案反查厂商名下全部域名 → 备案主体一致即可测
4. 子公司/收购主体：工商信息查关联公司 → 备案一致才测，存疑就问平台运营

## 2. 教育 SaaS 攻击面（厂商侧，主战场）

| 系统 | 高发洞型 |
|------|----------|
| 教学平台（泛雅/学习通类） | 跨租户越权（见 experience/cn-saas-tenant-bypass.md）、课程/作业 ID 遍历 |
| 在线考试/刷题 | 考试 ID 遍历他人答卷、成绩导出未鉴权、考生身份证号回显 |
| 客服/AI 机器人平台 | guest 登录零凭据、机器人 ID 遍历对话记录、配置接口泄 appKey |
| 学工/一网通办（厂商交付） | 交付时默认口令未改、debug 接口残留 |
| APP + 小程序 | 接口鉴权弱于 Web（同 src-hunter mobile playbook） |

教育行业数据敏感性排序：身份证号 > 家庭住址/家长信息 > 成绩 > 学习行为——报告里对应危害描述。

## 3. 高校自建系统（仅当列入范围时）

- 常见栈：正方/强智/青果教务、一网通办 ehall、各院系站群（多为老旧 CMS）
- 高频命中：学号=账号的弱口令、ehall 应用未授权、站群备份文件（/bak/、web.rar）、短信接口轰炸
- 证书/编号路线友好：同漏洞多校复现凑案例（见 cnvd-cnnvd 技能）

## 4. 国企/政企（谨慎区）

- 攻击面泛化：老旧 CMS、VPN 弱口令、邮箱口令复用、第三方外包系统
- **红线**：能源/金融/交通/政务类=关键信息基础设施，未获明确书面授权不测；扫到即停
- 外包系统是薄弱点：查厂商备案归属，SaaS 多客户部署可按厂商资产测

## 5. 实战节奏（快攻模式）

1. 平台选厂商 → 30 分钟摸清产品形态（SaaS 还是交付部署）
2. SaaS 类直接套多租户 playbook；交付类先过指纹库（chinese-srcfingerprints.md）再打对应 OA 洞
3. 2 小时无收获 → 换厂商（教训：A/B 双向闭环确认打不通就止损）
4. 命中即按 evidence-discipline 留证，当天提交（公益平台响应快，拖久易被别人重报）
