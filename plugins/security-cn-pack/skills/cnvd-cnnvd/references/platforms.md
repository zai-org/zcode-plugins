# 平台选择与 CNVD 证书细则

## 平台现状（2026）

- **漏洞盒子 / 补天**：范围广、国内站点都收、难度低——新手首选。**先读平台收录标准再挖**（某平台不收反射 XSS 就别浪费时间）；严格读测试范围，越界=非法测试
- **各厂 SRC**（腾讯/阿里/京东/字节等）：范围小、内卷、流程规范；字节有 AI 报告规范（AI 可挖但须人工验证，5 假报告封号）
- **EduSRC / 学校系统**：安全性低、案例多、易凑数（CNVD 案例）
- **CNVD**：证书路线；**CNNVD**：编号路线（IoT 自购设备→固件→漏洞→报送可行）
- 乌云/漏洞银行已死，老文章里的 17 平台清单别再当现状用

## CNVD 证书细则（干货）

- **通用型门槛**：中危及以上（CVSS2.0≥4.0）+ **厂商注册资金 5000w 以上**
- **黑盒案例结构**：**10 个测试案例（3 个完整复现 + 7 个其他，越多越好）**
- **事件型**：需高危 + 重要机构（党政机关、央企、部委直属）
- **目标定位三路**：
  1. 注册资金超 5000w 的网络科技/软件公司——产品站页脚找"技术支持：xx网络科技"
  2. 白盒审计大厂 CMS
  3. EduSRC 学校系统
- **案例凑数流程**：一个通用型漏洞用 fofa body 特征 / 谷歌语法（标题、URL、公司名）/ 厂商官网客户列表 / 搜狗必应，在多家单位复现即可凑满 10 案例
- **白盒案例纪律**：只交源码漏洞点+代码调试过程截图，**不混写黑盒案例**（混写会被审核误判，需发邮件申诉）
- **定级参考**：中危=任意密码重置/越权/SQL 注入/绕过登录；高危=命令执行/文件上传
- 拿到 shell 找不到足够案例时：下载管理员备份的源码，转白盒审计出证书
- 网络设备弱口令也可按黑盒要求出证书

## 目标选择经验

- 业务安全两薄弱环节：**非普通用户权限**（商家/合作方/签约作者——可社工获取测试账号）+ **新上线业务**（盯厂商公众号动态第一时间测）
- IP 段分核心段/边缘段/云服段——**边缘段测试机是最佳突破口**（不关 debug、弱口令、不入安防套餐）
- whois 注册人邮箱 → 扩展域名；备案号 → 同公司资产
- 403/404 站点更易出洞：先轻量扫目录（BBscan 类）再参数爆破；重型扫描器（AWVS）会被安防套餐封 IP
- 强安全策略下也有强弱口令：外部公开撞库字典匹配是现实威胁

## 新手入手点排序

意见反馈/文件上传等提交表单、付款金额校验、修改密码 sign 值替换、数值溢出——**新手从并发逻辑漏洞开始**（每个网站多少都有）。
