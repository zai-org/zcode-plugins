# 报告写作与定级

## 报告五要素

1. **接口地址（Target）**——精确到 endpoint
2. **来源地址（Referer）**——从哪个页面/入口发现
3. **Payload（Raw）**——完整 HTTP 原始包
4. **利用步骤**——每步可执行、可重现（假设审核者 5 分钟内要重现）
5. **危害描述**——业务影响，不是技术名词堆砌

其他纪律：
- 不同类型/业务线漏洞**分开提交**
- 报告内容**不传第三方网盘**
- 标题 ≤80 字，精确到 endpoint+漏洞类型

## 报告三段式模板

```
【标题】<漏洞类型> at <endpoint>（≤80字）

一、重现步骤
1. 访问 <URL>（Referer: <来源>）
2. 抓包替换参数 <param>: <A账号值 → B账号值>
3. 返回包包含 <字段>（截图）

原始 HTTP 包：
<Raw request + response 关键部分>

二、影响
<业务影响描述：可遍历 N 万用户资料/可接管任意账号/可免支付下单>
CVSS vector: <CVSS:3.1/AV:N/...>

三、修复建议
<鉴权位置/白名单/最小权限建议>
```

## 定级公式

**漏洞定级 = 敏感数据有无 + 利用成本 + 危害面积**

- 严重级判定 = **业务影响大 × 范围广**（测试库漏洞不算严重；技术难度高但业务影响小不定严重）
- 中危参考：任意密码重置、越权、SQL 注入、绕过登录
- 高危参考：命令执行、文件上传、域控

## 危害提升链（单点低危 → Critical）

| 单点 | 升级方向 |
|------|----------|
| XSS | → 窃取 cookie → ATO（账号接管）；+CSRF 组合 |
| self-XSS | + 登录页 CSRF / clickjacking / 授权缺陷 → stored XSS |
| SSRF | → 云元数据凭证 → 内网 RCE |
| IDOR | → 遍历 = 变相脱裤（强调危害面积） |
| 逻辑漏洞 | → 资金损失/他人余额支付 |
| 未授权服务 | → 写文件 → RCE |
| 反射型 XSS | + HTTP 走私/缓存投毒 → 存储型 |
| 开放重定向 | + SSRF 组合 |
| SQLi | + into outfile → RCE |

**影响 > 检测**：证明凭证窃取/RCE/数据外泄，不是"发现 XSS"。

## 提交技巧十条

1. 链式漏洞组合上报（开放重定向+SSRF、SQLi+文件写入=RCE）
2. 完整文档：截图、HTTP 请求、实际提取的数据（自己的测试数据）
3. 新颖技术：解析器混淆、mXSS、WAF 绕过链
4. 盲漏洞需证明：Interactsh/bXSS 实际回连记录
5. 越权必须有 A/B 账号对照（防误伤+防平台质疑）
6. self-XSS 别直接交，先想升级路径
7. 403 不是终点：换方法/换角色/换版本/换路径四种姿势
8. 403/404 站点先扫目录再放弃
9. 错误消息是金矿：无效值常返回有效值列表，截图留证
10. 提交后保留原始包+截图 ≥ 披露窗口期结束

## AI 辅助报告纪律（ByteSRC 规范）

AI 可以辅助挖洞和写报告，但必须**人工验证**——5 份假报告封号；报告中的每一步重现必须自己跑通。
