# Typst Workbench for ZCode

[简体中文](README_CN.md) | English

Write Typst documents with the agent and watch them typeset live in a side panel. The plugin uses **the Typst installed on your computer** — your fonts, your downloaded packages and your Typst version — so the preview matches what `typst compile` produces in your terminal. The preview updates within a fraction of a second whenever a file is saved, whether you or the agent changed it. The agent gets Typst's errors with file, line and hints, looks at rendered pages as images, points at places in your preview, and exports PDFs. You can select text in the preview and send it to the agent together with the source lines it comes from.

The Git marketplace package contains the compiled MCP server and panel; nothing needs to be built. It needs:

- Node.js 24+ and a ZCode Desktop build with Plugin UI support in a local workspace (web, phone and remote workspaces show plain tool records instead of the panel);
- **Typst 0.12 or later** installed on the same computer, for example `brew install typst` (macOS), `winget install --id Typst.Typst` (Windows), `cargo install --locked typst-cli`, or a release from <https://github.com/typst/typst/releases>.

The plugin looks for `typst` on `PATH`, in common install locations (Homebrew, Cargo, `~/.local/bin`, Nix, Snap, WinGet, Scoop) and finally in your login shell (for version managers such as mise or asdf). If Typst is installed somewhere else, set **Typst path** in the plugin settings.

## Use

Install and enable `typst-workbench`, then ask for example:

- "Start a two-column paper in Typst with a title block and an abstract."
- "Fix the errors in my thesis and show me what changed."
- "The table on page 3 overflows — make it fit."
- "Export `paper.pdf` as PDF/A-2b."

You can also open the panel from the side pane "+" menu.

### Panel

- **Setup** when Typst is missing, too old or broken: a checklist of what the panel found (and where it looked), your system and package managers, and a ready-made message that **Send to agent** posts to the chat so the agent installs it (**Copy** works with any other agent). *Install it yourself* shows the command for your system. The panel checks again every few seconds and opens the preview as soon as Typst runs.
- **Live preview** of the main file. Each save recompiles incrementally with `typst watch` and the visible pages are redrawn in place — no flicker, and the scroll position stays where it was. Zoom (fit width, fit page, or a percentage), page box, and an **Outline** of the headings.
- **Main file**: picked automatically (`main.typ`, or the only `.typ` file); switch it from the file menu in the toolbar. The choice is remembered for the workspace. With several candidates and no obvious one, the panel asks.
- **Status and problems**: the toolbar shows *compiling*, the compile time, or the number of errors and warnings. When the document does not compile, the last good version stays visible (dimmed) and the **Problems** panel lists each error with its location, source line, Typst's hints and the call trace. **Fix with agent** sends them to the agent; **Add to chat** adds them to the agent's context.
- **Selection to source**: select text in the preview and the toolbar that appears shows where it comes from (e.g. `sections/intro.typ:12`). **Add to chat** puts the passage and its source lines into the agent's context; **Ask** sends your question with them. **⌘-click** (Ctrl-click on Windows and Linux) a line to see its source location and excerpt.
- **Agent highlights** (purple, marked ✦) show what the agent points at; click one for its comment, or remove it.
- Follows ZCode's theme (light / dark) and language (English / Simplified Chinese).

Source locations come from matching the rendered text against the `.typ` files, because the Typst command line does not report where each piece of output comes from. They are reliable for prose, and approximate for math, numbering, outlines, bibliographies and text generated by functions. ZCode does not offer panels a way to open a file in the editor, so locations are shown and sent to the chat.

### Tools

| Tool | Purpose |
| --- | --- |
| `status` | Typst version and path, main file, other `.typ` files, latest compile result; opens the panel |
| `set_main` | Choose the main `.typ` file |
| `check` | Wait until every saved change is compiled, then report errors and warnings with location, source line, hints and trace |
| `render_pages` | Render up to 4 pages to PNG images for the agent to look at |
| `show` | Scroll the preview to a page, or highlight rendered text or the output of source lines, with a comment |
| `clear_highlights` | Remove agent highlights |
| `export_pdf` | Compile a PDF into the workspace (optional PDF standard and page selection) |

### Permissions, privacy and network

- The plugin runs your `typst` (or the file set in *Typst path*) with the workspace as the working directory, exactly as you would in a terminal: the project root is the main file's folder, and `TYPST_ROOT`, `TYPST_FONT_PATHS` and `TYPST_PACKAGE_PATH` in ZCode's environment apply.
- The plugin never edits `.typ` files. It writes into the workspace only when the agent calls `export_pdf`, and only inside the workspace. The preview PDF and rendered images live in the plugin's private data folder and are deleted when the session ends.
- The plugin itself does not use the network. Typst downloads `@preview` packages on first use, as it does in a terminal.
- ZCode asks for approval before tool calls as configured.

## Build from source

The source is in `ui-plugins/typst-workbench`. From the repository root:

```sh
pnpm install --frozen-lockfile
pnpm build
```

Add the absolute path of `dist/local-marketplace` as a local marketplace in the plugin store, then install and enable `typst-workbench`. After source changes, rebuild, refresh the source, reinstall the plugin and test in a new session.

Tests (from `ui-plugins/typst-workbench`):

```sh
pnpm test        # unit tests, every tool against a simulated typst CLI, and the main flows against the installed Typst
pnpm test:e2e    # built server and panel in Chrome through the official AppBridge host, with the installed Typst
pnpm test:setup  # the setup page in Chrome: missing Typst, hand-off to the agent, Typst appearing (simulated)
TYPST_TEST_BINARY=/path/to/typst pnpm test   # run the real-Typst tests with another Typst version
```
