# hexin-index 的字段陷阱

替换自 `wind-index-traps.md`。全部来自对一只宽基指数的真实取数,不是推测。
每一条都是**静默**陷阱:工具正常返回、没有报错,但直接采用会得出错误结论。

> 实测在持牌终端上完成,**具体指数、个股与返回数值不予转载**。保留下来的是
> 字段行为、退化常量与量级关系——那才是可复用的部分,数值本身不是。

## 1. 估值分位默认 52 周;问「近 N 年」会把窗口悄悄降到 2 天

`hexin-index.index_data` 返回的 PE/PB 分位是**默认窗口**(实测元数据为
`起始交易日期: 截止日52周前` → `截止交易日期: 最新`,即 52 周)。它不提供 3/5/10 年分位。

**厂商行为已变,且变得更危险(复测确认)。** 在 query 里写「近 5 年」不再返回空行:

| query | 元数据里的窗口 | 返回值 |
|---|---|---|
| `<指数> 市盈率PE(TTM) 及其分位数` | `截止日52周前 → 最新`(真 52 周) | 一个正常量级的分位 |
| `<指数> 市盈率PE(TTM)近5年分位数` | **`截止日前一交易日 → 最新`(2 天)** | **100.0** |

它**静默把窗口缩到 2 天**,再返回一个看起来正常的 100.0。旧版记录的「返回空行」至少
是可见的失败;现在是不可见的失败。

**`分位数 = 100.0` 或 `1.0` 基本就是窗口退化的信号灯。** 看到就去查元数据窗口,不要直接用。

按覆盖度约定,**窗口未知的分位不得呈现**。所以更长窗口必须:

1. 用 `index_data` 取 PE/PB **日度序列**(实测一只宽基指数可取到约五年的日频点数);
2. 自算分位,标 `[测算]`,并把**回看窗口起始日与采样频率**写在数字旁边。

默认的 1 年分位可用于交叉验证自算结果。

## 2. 指数级 ROE:字段存在(此前记为缺口,实测推翻)

Wind 的 `get_index_fundamentals` 的「成份股ROE合计」是**成份股 ROE 的简单求和**,
量级在百分之数百,因此不能当作指数层 ROE 使用——它不是加权口径。
**同花顺有可用字段。** 实测 `index_data` 查「<指数> 净资产收益率」返回两个口径:

| 字段 | `indicators_params` 回读 |
|---|---|
| 净资产收益率(TTM) | 交易日期=最新, TTM基准日=报表截止日期 |
| 净资产收益率-平均 | 报告期=去年年报 |

两个数不是一回事,**必须回读 `indicators_params` 并把口径写在数字旁**:一个是 TTM
滚动、一个是上一年年报的平均值,混用会造出一个不存在的时点。两者数量级都在宽基指数的常见区间(个位数百分比),
与上面那个求和口径不是一回事。

`隐含 ROE = PB / PE`(同一时点、同一数据源的两个倍数相除)现在是**交叉校验**手段,
不再是替代口径——两者差得远时,先怀疑 PE/PB 取自不同调用或不同指数代码(见第 3 节)。
恒等式 `PE / PB ≡ B / E ≡ 1 / ROE` 仍应在报告里写出来,因为它解释了 PE 分位与 PB 分位
之所以能裂开——分母变了,不是价格贵了。

## 3. 同一指数跨调用会漂移到不同代码

同一只宽基指数在一次查询里返回**沪市代码**,在另一次(尤其分位查询)返回**深市代码**。
**跨调用拼接序列时按 名称 匹配,不要按代码** —— 否则会以为拿到了两个指数。

## 4. 序列调用有截断

`index_data` 返回「为您找到 N 条数据,以下为部分数据」并截断(实测 PE 日序列有数千条
但只回前若干行)。要完整序列需要分页或收窄窗口,别把截断后的前几行当成全部。

## 5. 单位列标不可信

返回的列头标「单位:元」不代表值就是元 —— 同一列在不同调用里单位会变(元/亿/%)。
**从响应里读回单位并写进来源行**,不要凭记忆。

## 6. `sector_data` 会用散文编出一个不存在的分位数,而且是随机发作

实测于一个行业板块,**同一 query 连发 6 次**。

`sector_data` 的 `indicators_params` 里**只有 `市盈率(TTM,整体法)`,没有分位数指标**——
6 次调用全都如此。但散文答案不一致:

| 次数 | 散文答案 |
|---|---|
| 4 次 | 正确说明「历史分位数的数据并未在提供的信息中给出」 |
| **2 次** | **「历史分位数为 1.0…这意味着当前市盈率处于历史最高分位」** |

同一 query、同一参数、同一份 `indicators_params`,结果时对时错。**所以「测了一次没问题」
不构成任何保证**——这是这条陷阱最难防的地方,它不是稳定错误,是间歇性错误。

那个 1.0 是拿**单个观测**算出来的(一个点的分位必然是 1.0),与真实分位无关。

### 不要用「看起来对不对」来判断

第一次发现时,我们判断「1.0=最高分位」方向错了。**这个判断本身是错的**——事后用
`index_data` 取同一板块指数的**真实**分位字段(在 `indicators_params` 里),
结果是一个**接近 98% 的高分位**。

也就是说:编造的 100% 与真实的高分位相当接近,**编造出来的数字可能恰好落在合理区间里。**
这正是不能靠人眼合理性来筛的原因——一个看起来对的幻觉比一个荒谬的幻觉危险得多。

(注意两个 PE 不可直接比:`sector_data` 的板块整体法 PE 与 `index_data` 的板块指数 PE
是不同口径、不同成份集,两者数值有明显差距。那个高分位属于后者。)

### 判据

**`indicators_params` 是唯一权威,散文答案不是。**
任何数字,若在 `indicators_params` 里找不到对应指标,就不是取回来的字段,而是厂商
自然语言层的推断——不得作为 `[披露]` 引用,通常应直接丢弃。判断依据是**字段有无**,
不是数值是否合理。这条对所有同花顺 server 都成立,`sector_data` 的分位数只是目前
证据最完整的一例。

## 7. `sector_data` 的主体要带「板块分类体系」

厂商在工具说明里自己写了:「由于板块命名具有相似性,请尽可能提供板块所属分类信息」,
样例是 `医疗设备板块(中证行业)`。实测四种写法:

| query 主体 | 结果 |
|---|---|
| `<板块名>板块(申万行业)` | 正常返回 成份股个数 与 市盈率(TTM,整体法) |
| `<板块名>板块`(名称无歧义时) | 也能解析,返回 成份股个数 / 总市值 / PE |
| `申万一级行业 <板块名>` | 只有表头的**空表** |
| `<板块名>板块`(名称有歧义时) | `查询结果为空` |

**正确写法是 `<板块名>板块(<分类体系>)`**,分类体系如 `申万行业` / `中证行业`。
不带分类时,只有无歧义的板块名才碰得对。

空表**不是**「该板块没有数据」,是主体没解析成功。按缺失处理会把一次失败的查找
写成 `检索范围内未发现`,那是假阴性。补上分类体系重问,并回读 `板块名称` 确认
解析到的是哪个板块;确实解析不出来再退回枚举成份股。

## 8. `get_stock_financials` 的估值分位窗口是**单日**,恒等于 100.0

实测于一只 A 股个股:

```
市盈率(PE,TTM)分位数 = 100.0
indicators_params: {"市盈率(PE,TTM)分位数": {"起始交易日期":"最新","截止交易日期":"最新"}}
```

`起始交易日期` 与 `截止交易日期` **都是「最新」——窗口只有一天**,所以分位必然是 100.0。
改问「近 5 年历史分位数」窗口也不变,依旧 100.0。

**这个字段对任何分位判断都不可用。** 它与 §6 的散文编造是两种不同的坑:这里是
**真字段、真元数据**,坑在窗口本身退化。所以「字段在不在 `indicators_params` 里」
只是第一道筛,**还必须读里面的窗口**。

**个股估值分位改用 Wind,不必自算。** 实测同一只股同一天,两家的 PE 值一致,但分位:

```
同花顺 get_stock_financials   分位数 = 100.0                (窗口单日,不可用)
Wind   get_stock_fundamentals 分位数 = 一个中低分位值        (并返回 序号 / 最大序号)
```

Wind 把**排名与样本量都返回了**,可自行复算(序号 ÷ 最大序号),窗口也写在列名里
(「最新市盈率在过去一年中的分位数」)。指数层同理走
`wind-index.get_index_fundamentals`,且支持近5年。**两家的分位不可混用**——口径与样本不同。

## 9. 同花顺与 Wind 的分位数不可混用

实测同一只宽基指数、同一天:

| 源 | PE(TTM) | 1年分位 | 依据 |
|---|---|---|---|
| 同花顺 `index_data` | 两家几乎一致 | 较低的那个 | 52 周窗口,剔除规则不调整 |
| Wind `wind-index.get_index_fundamentals` | 两家几乎一致 | 较高的那个 | **返回 序号 / 最大序号**,可复算 |

两者相差 **约 12 个百分点**。对一份以「PE 处于 X 分位」开头的交付物,这就是「区间中部」
与「偏上三分之一」两种结论。原因是样本与口径不同(周频 52 点 vs 一年的交易日点数),
两个都不算错。

Wind 还支持更长窗口且窗口写在列名里:同一个 PE,近一年与近五年的分位可以差出
**二十个百分点以上**——这就是窗口为什么必须写出来。

**判据:分位数只走 Wind;同一张表、同一次比较里不得出现两家的分位。** 每个分位旁边写明
厂商、窗口、口径,并把 Wind 的 排名/最大排名 一并列出供复算。
