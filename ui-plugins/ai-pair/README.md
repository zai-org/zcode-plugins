# ai-pair

AI Pair 评审：主对话完成代码/内容创作后，把成果送 **两个异构模型** 并行评审，在会话侧栏面板查看分级报告。模型渠道完全复用 ZCode「管理模型」里已配置的渠道，插件里**不需要单独填 API Key**。

## 用法（对话里）

- "改完了，送 ai-pair 评审" / "让两个模型评一下刚才的改动"
- Agent 会调用 `request_review` 工具（传 diff 或文件列表），评审后台运行，侧栏「AI Pair 评审」面板自动刷新
- `get_review` 取完整报告；`list_reviews` 列历史；`list_models` 列渠道与实测连通性

## 配置（推荐：面板级联选择）

侧栏「AI Pair 评审」面板 → **⚙ 设置**：两个评审位各自 **渠道下拉 → 模型下拉 → 保存**，
渠道与模型来自 ZCode「管理模型」的已有配置，密钥自动复用、无需手填，保存立即生效。

也可在对话里让 AI 跑 `configure_reviewers` 工具（如"评审模型 1 用 Kimi 的 k3.1-pro"）。

### 评审员角色定义

两个评审槽位是**固定分工**（借鉴原版 ai-pair 的具名评审员模式），角色由插件注入每次评审的提示词，不随所选渠道变化：

| 评审位 | 角色 | 代码评审重点（focus=dev） | 内容评审重点（focus=content） |
| --- | --- | --- | --- |
| 评审模型 1 | **正确性把关** | bug、安全漏洞、并发问题、性能、边界条件、错误处理 | 逻辑严密性、事实准确性、无依据的论断、内部矛盾、缺少引用 |
| 评审模型 2 | **设计与可维护性** | 架构与模块边界、设计模式、可读性与可维护性、命名、未来隐患 | 可读性、结构与行文节奏、语气与风格一致性、受众契合度、标题与开头 |

评审模型 2 建议选**不同厂商**的渠道——两个模型加两个视角，异构评审的价值才在；
结论冲突时插件不做仲裁，并列呈现交由用户裁决。

支持的渠道协议：OpenAI chat/completions 与 Anthropic messages（自动识别）。
需要新渠道时直接在 ZCode「管理模型」里添加，插件面板重开即能看到。

> 隐私说明：提交评审的 diff 与文件全文会发送到**你自己配置的模型渠道**（由所选渠道的厂商处理），
> 评审记录仅保存在本机插件数据目录；API Key 只在插件服务端内存中使用，不落盘、不下发面板。

## OpenCode Go 渠道注意

- Go 网关要求 `x-opencode-session` 会话头与自定义 User-Agent —— 插件对 `opencode.ai` 域名自动处理
- OpenCode 隐私设置默认屏蔽部分模型（如 DeepSeek 系），需在 OpenCode Settings › Privacy 开启

评审数据存放在插件持久目录（按工作区隔离）。
